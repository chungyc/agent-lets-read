# Let's Read Skill (Spoiler-Free Architecture)

This skill enables a genuine, unspoiled **Let's Read** of a story or book in `.txt`, `.md`, `.html`, or `.epub` format. It solves the fundamental problem of AI Let's Reads—accidentally reading ahead or leaking future plot points into context—by combining a **Haskell Gatekeeper** ([LetsRead.hs](./scripts/LetsRead.hs)) with a sandboxed **Blind Reader Subagent**.

---

## Mandatory Anti-Spoiler Rules

1. **NEVER Read the Source Story File Directly**:
   - Do **not** call `read_file`, `grep_search`, or `head`/`cat` on the user's source story file.
   - Only pass the source file path to `LetsRead.hs init`.
2. **NEVER Inspect `.vault.bin`**:
   - `LetsRead.hs init` encodes all story chunks into `<session_dir>/.vault.bin` (an XOR-obfuscated binary archive) so neither `grep_search` nor file inspection can leak future text.
3. **Do NOT Read or Inspect `LetsRead.hs`**:
   - Treat `LetsRead.hs` as a black-box tool. Run it strictly using the CLI commands documented below; do not read or inspect its source code.
4. **Do NOT Pass `--max-words` Unless Requested**:
   - Never pass `--max-words` when initializing sessions unless the user explicitly asks for a custom chunk size. Always let `LetsRead.hs` use its built-in default.
5. **Strict Subagent Isolation & Verified Archive Access**:
   - All reading and commentary generation must be performed by a dedicated `blind-reader` subagent created with `EnableWriteTools: false`.
   - Never tell the `blind-reader` subagent the path to the original source story file, and never allow it to inspect `<session_dir>/.vault.bin` or local workspace files outside `<session_dir>`.
   - **Background Lore Searches Allowed**: While `blind-reader` must never search the web for the *specific story being read*, it **may** freely use `search_web` (and its training knowledge) to look up background canon lore, source-material context (e.g., for fanfiction, crossovers, sequels, or adaptations), fandom theories, or historical/literary allusions.
   - Pass it the paths to (auto-generated in `<session_dir>/current_prompt.md` by `LetsRead.hs next`):
     - `<session_dir>/current_chunk.md` (current unlocked story chunk — mandatory read every turn)
     - `<session_dir>/memory.md` (running summary, theories, and auto-maintained archive/index tree — mandatory read every turn)
     - `.agents/skills/lets-read/resources/commentary_template.md` (flexible commentary structure guide — allowed on-demand via `read_file`)
     - `<session_dir>/archive/` (multi-level arc archive files `L1_XXXX.md`, `L2_XXXX.md`, and historical memory snapshots `archive/memory/chunk_XXXX.md` — allowed on-demand via `read_file`)
     - `<session_dir>/chunks/` (previously unlocked story chunks `chunk_0001.md` .. `chunk_XXXX.md` — allowed on-demand via `read_file` to verify callbacks and quotes without hallucinating)
     - `<session_dir>/entries/` (previously recorded Let's Read commentary `chunk_0001.md` .. `chunk_XXXX.md` — allowed on-demand via `read_file`)
6. **NEVER Impersonate `blind-reader`, Answer Story Questions Directly, Edit `memory.md` Directly, or Paste Chunks/Memory Inline**:
   - You (the parent orchestrator) are strictly the **session host and gatekeeper relay**, never the reader.
   - Never answer a user's question, comment, or observation about the story in your own voice, and never call `edit_file` or `write_file` directly on `<session_dir>/memory.md` (all updates must flow through `LetsRead.hs record` or `LetsRead.hs discuss`).
   - **Never paste `current_chunk.md` or `memory.md` inline into prompts** to `blind-reader` or improvise custom subagent prompts after context compaction. Always read `<session_dir>/current_prompt.md` (generated by `LetsRead.hs next`) and pass its contents to `blind-reader` so `blind-reader` reads `current_chunk.md` and the full `memory.md` directly from disk.
   - Whenever presenting `blind-reader`'s commentary or discussion reply in chat, always prefix your message with a clear third-person host banner (e.g. `> **Let's Read Host** — Relaying from \`blind-reader\` (Chunk XXXX/YYYY):`) so the conversation history and any context compaction summaries always preserve the boundary between the host and `blind-reader`.

## Workflow

### Step 1: Clarify Session Preferences (If Not Specified)

If the user has not specified their preferences, briefly check or choose sensible defaults:
- **Mode**:
  - **Interactive Mode** *(default)*: Read one chunk (or one chapter) at a time, display the commentary in chat, and pause so the user can discuss theories or say "continue".
  - **Batch Mode**: Autonomously read a specified number of chunks/chapters (or the entire work), recording all updates into `<session_dir>/lets_read_log.md`.
- **Reader Persona**: See [personas.md](./references/personas.md) for presets (default: *Classic Forum Liveblogger*).
- **Session Directory**: Default to `./lets-read-sessions/<story-slug>/` (or a user-specified directory).

### Step 2: Initialize the Gatekeeper Session

Read [personas.md](./references/personas.md) if a custom tone was requested. Ensure the shared gatekeeper binary `.agents/skills/lets-read/.bin/lets-read` is compiled and up to date (rebuilding only if missing or if `LetsRead.hs` is newer), then initialize the session:

```bash
if [ ! -x .agents/skills/lets-read/.bin/lets-read ] || [ .agents/skills/lets-read/scripts/LetsRead.hs -nt .agents/skills/lets-read/.bin/lets-read ]; then
  mkdir -p .agents/skills/lets-read/.bin
  ghc -O2 -outputdir .agents/skills/lets-read/.bin -o .agents/skills/lets-read/.bin/lets-read .agents/skills/lets-read/scripts/LetsRead.hs
fi

.agents/skills/lets-read/.bin/lets-read init "<source_story_path>" \
  --session "<session_dir>" \
  --persona "<chosen_persona>"
```

Verify the JSON output from `init`, which reports `total_chapters`, `total_chunks`, `total_words`, `memory_file`, and `log_file` without revealing any future chapter titles or story text.

### Step 3: Define the `blind-reader` Subagent

Read [reader_system_prompt.md](./resources/reader_system_prompt.md) and call `define_subagent`:
- `Name`: `"blind-reader"`
- `Description`: `"Sandboxed first-time reader that reacts to one unlocked story chunk at a time without access to future chapters."`
- `SystemPrompt`: The contents of [reader_system_prompt.md](./resources/reader_system_prompt.md).
- `EnableWriteTools`: `false`
- `EnableSubagentTools`: `false`
- `EnableMCPTools`: `false`

### Step 4: Unlock, React, and Record (The Reading Loop)

For each chunk to be read:

1. **Unlock the Next Chunk**:
   ```bash
   .agents/skills/lets-read/.bin/lets-read next --session "<session_dir>"
   ```
   This unlocks the next chunk into `<session_dir>/current_chunk.md`, writes the canonical subagent prompt to `<session_dir>/current_prompt.md`, archives a permanent copy into `<session_dir>/chunks/chunk_XXXX.md`, updates `<session_dir>/story_so_far.md` (containing only chunks `1..current`), and prints spoiler-free metadata (`chunk_index`, `total_chunks`, `chapter_number`, `chapter_title`, `part_in_chapter`, `parts_in_chapter`, `word_count`, `subagent_prompt_file`).
   - *Guardrail*: `LetsRead.hs next` will refuse to advance if the previous chunk's commentary has not been recorded yet.

2. **Invoke or Message `blind-reader` (Using `<session_dir>/current_prompt.md`)**:
   - **First chunk (or at a chapter boundary after >= 6 chunks when `LetsRead.hs next` returns `"rotate_subagent_recommended": true`)**: Call `invoke_subagent` with `TypeName: "blind-reader"` and `Role: "Blind Story Reader"`.
   - **Consecutive chunks**: Call `send_message` to the active `blind-reader` `conversationId` so it retains immediate conversational momentum across multi-part chapters.
   - **Prompt to `blind-reader`** (read from `<session_dir>/current_prompt.md` — never paste `current_chunk.md` or `memory.md` inline):
     ```text
     Please read the newly unlocked chunk (Chunk <X> of <Y>) and update your Let's Read commentary and memory.
     - Current Chunk File (mandatory read): <absolute_path_to_session_dir>/current_chunk.md
     - Reader Memory File (mandatory read): <absolute_path_to_session_dir>/memory.md
     - Previous Commentary Entry (mandatory self-audit read): <absolute_path_to_session_dir>/entries/chunk_(X-1).md
     - Previous Story Chunk (read if newly rotated or mid-chapter): <absolute_path_to_session_dir>/chunks/chunk_(X-1).md
     - Commentary Guide Template (flexible reference): <absolute_path_to_commentary_template.md>
     - Multi-Level Memory & Index Archive (on-demand read_file): <absolute_path_to_session_dir>/archive
     - Unlocked Story Chunks Archive (on-demand read_file): <absolute_path_to_session_dir>/chunks
     - Previous Commentary Entries (on-demand read_file): <absolute_path_to_session_dir>/entries
     - Active Persona: <persona>

     Remember:
     1. Read `current_chunk.md` and `memory.md` first (plus `entries/chunk_(N-1).md` for self-audit when Chunk > 1, and `chunks/chunk_(N-1).md` if you are a newly rotated subagent or picking up mid-chapter). Reference `commentary_template.md` as a flexible guide; custom scene or thematic `###` subheadings are welcome, but do not start `=== COMMENTARY ===` with a redundant `# Chunk X/Y` header.
     2. Self-Audit & "Egg-on-Face" Rule: Before writing your reaction, compare what just happened in `current_chunk.md` against your previous entry (`entries/chunk_(N-1).md`) and your predictions in `memory.md`. If the story subverted your expectations or pulled a fake-out that tricked you—especially if a character in the story had the exact same misconception you just had—call yourself out openly! Never gloss over a wrong theory or pretend you knew all along, and never take a victory lap ("I called it!") on an obvious 1–2 chunk cliffhanger guess right after getting fooled.
     3. Enforced Prediction Notation (Audited by `LetsRead.hs`):
        - Active predictions in `## Active Predictions & Theories` MUST use exact notation: `- **[Predicted Chunk XXXX]** *Clue*: ... -> *Theory*: ... *(vs. Plausible Rival: ...)*`
        - Resolved predictions MUST be moved to `## Hall of Fame & Shame (Major Hits & Misses)` with exact notation: `- **[Predicted Chunk XXXX -> CONFIRMED Chunk YYYY]** ...`, `- **[Predicted Chunk XXXX -> DEBUNKED Chunk YYYY]** ...`, or `- **[Predicted Chunk XXXX -> SUBVERTED Chunk YYYY]** ...`.
        - Never use `[Refined ...]`, `[Updated ...]`, or `[Active / Refined ...]`, never rewrite an existing prediction's text in place to fit new facts, and never silently drop an unresolved prediction. If `LetsRead.hs` injected a `[READER SUB-AGENT REWROTE PREDICTION OR MOVED GOALPOSTS IN FILE ...]` block into `memory.md`, you MUST address it openly in your commentary and either restore the exact `*Before*` prediction or resolve it with `CONFIRMED`/`DEBUNKED`/`SUBVERTED` in `## Hall of Fame & Shame`.
     4. Quote verbatim from `current_chunk.md` (inserting `[...]` if skipping intervening stage directions). Never "double-tell" by summarizing what a quote says right before or right after quoting it, and never append a `Key Developments` summary bullet list to `=== COMMENTARY ===`.
     5. Whenever you reference, quote, or compare specific scenes, predictions, or dialogue from an earlier chunk that is not in your immediate conversation history, verify it first using `## Memory Archive & Index Tree` in `memory.md` (following links into `<session_dir>/archive/L1_XXXX.md` if needed, then reading `<session_dir>/chunks/chunk_XXXX.md`, `<session_dir>/entries/chunk_XXXX.md`, or `<session_dir>/archive/memory/chunk_XXXX.md`). Never invent quotes or scene details from condensed `memory.md` bullets.
     6. Never inspect `.vault.bin` or any local file outside `<session_dir>` (except `commentary_template.md`), and never search the web for the specific story being read (using `search_web` for background canon/franchise lore or allusions is welcome).
     7. Output all three required sections: `=== COMMENTARY ===`, `=== CHUNK SUMMARY ===` (1 line), and `=== UPDATED MEMORY ===` (all 6 curated sections; `LetsRead.hs` automatically maintains `## Memory Archive & Index Tree`).
     ```

3. **Record Commentary & Updated Memory**:
   Write the subagent's full reply to `<session_dir>/last_response.md` using `write_file` (with `Overwrite: true`), then run:
   ```bash
   .agents/skills/lets-read/.bin/lets-read record \
     --session "<session_dir>" \
     --response-file "<session_dir>/last_response.md"
   ```
   `LetsRead.hs record` automatically:
   - Splits `=== COMMENTARY ===`, `=== CHUNK SUMMARY ===`, and `=== UPDATED MEMORY ===`.
   - Saves the individual commentary update to `<session_dir>/entries/chunk_XXXX.md`.
   - Merges and deterministically audits the 6 curated memory sections (preserving any omitted section, tagging `<3`-chunk confirmations as `(Short-Horizon <3 Chunks — No Hit Credit)` in `Hall of Fame & Shame` rather than deleting them, and injecting `[READER SUB-AGENT REWROTE PREDICTION OR MOVED GOALPOSTS IN FILE <full_path>]` with `*Before*` and `*After*` if any prediction was rewritten in place, given an unknown/evasive notation like `[Refined ...]`, or silently dropped), appends the 1-line chunk summary to the multi-level archive tree in `<session_dir>/archive/`, saves the point-in-time memory snapshot to `<session_dir>/archive/memory/chunk_XXXX.md`, and updates `<session_dir>/memory.md`.
   - Rebuilds the master Let's Read thread at `<session_dir>/lets_read_log.md`.
   - Marks the current chunk as recorded so `next` can unlock the following chunk.

4. **Validation**:
   Verify that `LetsRead.hs record` outputs `"status": "recorded"` and check `remaining_chunks` (or run `LetsRead.hs status --session "<session_dir>"`).

### Step 5: Interactive Discussion vs. Batch Progression

- **In Interactive Mode**:
  - Present the `blind-reader`'s commentary for the chunk to the user, always prefixed with a third-person host attribution banner (`> **Let's Read Host** — Relaying from \`blind-reader\` (Chunk XXXX/YYYY):`), and link to `<session_dir>/lets_read_log.md` and `<session_dir>/memory.md`.
  - If the user replies with comments, questions, or non-spoiler discussion before asking for the next chunk:
    1. **Never answer in your own voice**: Forward their message (scrubbed of any spoilers, if applicable) to the `blind-reader` subagent via `send_message` so the reader persona can discuss theories with the user like a live forum thread host (and optionally output an `=== UPDATED MEMORY ===` block if the discussion updates its theories).
    2. Write `blind-reader`'s reply to `<session_dir>/last_response.md` and run `LetsRead.hs discuss` so the Q&A exchange is permanently recorded under `### Reader Discussion` in `<session_dir>/entries/chunk_XXXX.md` and `<session_dir>/lets_read_log.md` (and any memory updates are merged into `<session_dir>/memory.md` and `<session_dir>/archive/`):
       ```bash
       .agents/skills/lets-read/.bin/lets-read discuss \
         --session "<session_dir>" \
         --user-message "<user's comment or question>" \
         --response-file "<session_dir>/last_response.md"
       ```
    3. Present `blind-reader`'s reply to the user prefixed with the third-person host banner (`> **Let's Read Host** — Relaying discussion reply from \`blind-reader\`:`).
- **In Batch Mode**:
  - Repeat Step 4 until the target number of chunks/chapters (or `"status": "finished"`) is reached.
  - Whenever `LetsRead.hs next` outputs `"rotate_subagent_recommended": true` (at a chapter boundary after >= 6 chunks), start a fresh `blind-reader` subagent instance via `invoke_subagent` so its context window stays sharp and relies on the curated `<session_dir>/memory.md`.
