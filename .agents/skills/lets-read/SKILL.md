# Let's Read Skill (Spoiler-Free Architecture)

This skill enables a genuine, unspoiled **Let's Read** of a story or book in `.txt`, `.md`, `.markdown`, `.html`, or `.epub` format. It solves the fundamental problem of AI Let's Reads—accidentally reading ahead or leaking future plot points into context, as well as self-serving prediction grading—by combining a **Haskell Gatekeeper** ([LetsRead.hs](./scripts/LetsRead.hs)) with two sandboxed subagents:
1. **`blind-reader`**: Reads each newly unlocked chunk, reacts in character (including reacting to how the Judge ruled on its prior predictions), stakes 1 new multi-chapter prediction per chunk, and nominates a conditional retirement candidate when at the 10-prediction cap.
2. **`prediction-judge`**: Independently and impartially evaluates **all** active predictions (including the newly created prediction and any conditional retirement candidate) against `current_chunk.md` after `blind-reader`'s turn. Conditional retirement only triggers if more than 10 predictions remain active *after* `prediction-judge` renders its verdicts.

## Mandatory Anti-Spoiler Rules

1. **NEVER Read the Source Story File Directly**:
   - Do **not** call `read_file`, `grep_search`, or `head`/`cat` on the user's source story file.
   - Only pass the source file path to `LetsRead.hs init`.
2. **NEVER Inspect `.vault.bin`**:
   - `LetsRead.hs init` encodes all story chunks into `<session_dir>/.vault.bin` (an XOR-obfuscated binary archive) so neither `grep_search` nor file inspection can leak future text.
3. **Do NOT Read or Inspect `LetsRead.hs`**:
   - Treat `LetsRead.hs` as a black-box tool. Run it strictly using the CLI commands documented below; do not read or inspect its source code.
4. **Do NOT Pass `--max-words` Unless Requested**:
   - Never pass `--max-words` when initializing sessions unless the user explicitly asks for a custom chunk size. Always let `LetsRead.hs` use its built-in default.
5. **Strict Subagent Isolation & Verified Archive Access**:
   - All reading/commentary generation and all prediction judging must be performed by dedicated `blind-reader` and `prediction-judge` subagents created with `EnableWriteTools: false`.
   - Never tell either subagent the path to the original source story file, and never allow them to inspect `<session_dir>/.vault.bin` or local workspace files outside `<session_dir>`.
   - **Background Lore Searches Allowed**: While `blind-reader` and `prediction-judge` must never search the web for the *specific story being read*, they **may** use `search_web` (and their training knowledge) to look up background canon lore, source-material context (e.g., for fanfiction, crossovers, sequels, or adaptations), fandom theories, or historical/literary allusions.
   - Pass `blind-reader` the paths in `<session_dir>/current_prompt.md` (generated by `LetsRead.hs next`) and pass `prediction-judge` the paths in `<session_dir>/current_judge_prompt.md` (generated by `LetsRead.hs record`):
     - `<session_dir>/current_chunk.md` (current unlocked story chunk — mandatory read every turn)
     - `<session_dir>/memory.md` (running summary, auto-maintained archive/index tree, and auto-maintained active prediction slate — mandatory read for `blind-reader`, optional context for `prediction-judge`)
     - `.agents/skills/lets-read/resources/commentary_template.md` (flexible commentary structure guide — allowed on-demand via `read_file`)
     - `<session_dir>/predictions/` (auto-indexed prediction files: `by_chronology.md`, `by_topic.md`, `pred_XXXX.md`, and upon story completion `hall_of_fame.md` — allowed on-demand via `read_file`)
     - `<session_dir>/archive/` (multi-level arc archive files `L1_XXXX.md`, `L2_XXXX.md`, and historical memory snapshots `archive/memory/chunk_XXXX.md` — allowed on-demand via `read_file`)
     - `<session_dir>/chunks/` (previously unlocked story chunks `chunk_0001.md` .. `chunk_XXXX.md` — allowed on-demand via `read_file` to verify callbacks and quotes without hallucinating)
     - `<session_dir>/entries/` (previously recorded Let's Read commentary `chunk_0001.md` .. `chunk_XXXX.md` — allowed on-demand via `read_file`)
6. **NEVER Impersonate `blind-reader` or `prediction-judge`, Answer Story Questions Directly, Edit `memory.md` Directly, or Paste Chunks/Memory Inline**:
   - You (the parent orchestrator) are strictly the **session host and gatekeeper relay**, never the reader or judge.
   - Never answer a user's question, comment, or observation about the story in your own voice, and never call `edit_file` or `write_file` directly on `<session_dir>/memory.md` (all updates must flow through `LetsRead.hs record`, `LetsRead.hs judge`, or `LetsRead.hs discuss`).
   - **Never paste `current_chunk.md` or `memory.md` inline into prompts**, never improvise custom subagent prompts after context compaction, and never append ad-hoc memory-size or line-count nagging (such as `"keep memory under 4,000 bytes"`). Always read `<session_dir>/current_prompt.md` (for `blind-reader`) and `<session_dir>/current_judge_prompt.md` (for `prediction-judge`) and pass their contents verbatim.
   - Whenever presenting `blind-reader`'s commentary or discussion reply in chat, always prefix your message with a clear third-person host banner (e.g. `> **Let's Read Host** — Relaying from \`blind-reader\` (Chunk XXXX/YYYY):`) so the conversation history and any context compaction summaries always preserve the boundary between the host and `blind-reader`.
7. **NEVER Run `python`, `python3`, or Ad-Hoc Shell Scripts**:
   - Do **not** run `python`, `python3`, `node`, `perl`, or any ad-hoc shell/Python one-liners to extract subagent responses from `transcript.jsonl`, splice or pre-process `last_response.md` / `memory.md`, check byte/line counts, or escape multi-line strings.
   - `LetsRead.hs` handles all parsing, prediction auditing, Judge verdict application, chronological/topic prediction indexing, memory merging, byte/line counting, and subagent transcript extraction natively in compiled Haskell. Use strictly `.agents/skills/lets-read/scripts/prepare.sh`, `.agents/skills/lets-read/.bin/lets-read` (`init`, `next`, `record`, `judge`, `discuss`, `status`), `read_file`, `write_file`, and `manage_subagents`.

## Workflow

### Step 1: Clarify Session Preferences (If Not Specified)

If the user has not specified their preferences, briefly check or choose sensible defaults:
- **Mode**:
  - **Interactive Mode** *(default)*: Read one chunk (or one chapter) at a time, display the commentary and Judge rulings in chat, and pause so the user can discuss theories or say "continue".
  - **Batch Mode**: Autonomously read a specified number of chunks/chapters (or the entire work), recording all updates and Judge rulings into `<session_dir>/lets_read_log.md`.
- **Reader Persona**: See [personas.md](./references/personas.md) for presets (default: *Classic Forum Liveblogger*).
- **Session Directory**: Default to `./lets-read-sessions/<story-slug>/` (or a user-specified directory).

### Step 2: Initialize the Gatekeeper Session

Read [personas.md](./references/personas.md) if a custom tone was requested.

1. **Prepare the Gatekeeper Binary**:
   Run [prepare.sh](./scripts/prepare.sh) as a standalone command to ensure `.agents/skills/lets-read/.bin/lets-read` is compiled and up to date (rebuilding only if missing or if `LetsRead.hs` is newer):
   ```bash
   .agents/skills/lets-read/scripts/prepare.sh
   ```

2. **Initialize the Session**:
   Run `.agents/skills/lets-read/.bin/lets-read init` as a separate command:
   ```bash
   .agents/skills/lets-read/.bin/lets-read init "<source_story_path>" \
     --session "<session_dir>" \
     --persona "<chosen_persona>"
   ```

Verify the JSON output from `init`, which reports `total_chapters`, `total_chunks`, `total_words`, `predictions_dir`, `memory_file`, and `log_file` without revealing any future chapter titles or story text.

### Step 3: Define the `blind-reader` and `prediction-judge` Subagents

1. Read [reader_system_prompt.md](./resources/reader_system_prompt.md) and call `define_subagent`:
   - `Name`: `"blind-reader"`
   - `Description`: `"Sandboxed first-time reader that reacts to one unlocked story chunk at a time, proposes 1 new prediction per chunk, and nominates conditional retirement candidates without access to future chapters."`
   - `SystemPrompt`: The contents of [reader_system_prompt.md](./resources/reader_system_prompt.md).
   - `EnableWriteTools`: `false`
   - `EnableSubagentTools`: `false`
   - `EnableMCPTools`: `false`

2. Read [judge_system_prompt.md](./resources/judge_system_prompt.md) and call `define_subagent`:
   - `Name`: `"prediction-judge"`
   - `Description`: `"Impartial, unspoiled referee that evaluates all active predictions against the newly unlocked story chunk."`
   - `SystemPrompt`: The contents of [judge_system_prompt.md](./resources/judge_system_prompt.md).
   - `EnableWriteTools`: `false`
   - `EnableSubagentTools`: `false`
   - `EnableMCPTools`: `false`

### Step 4: Unlock, React, Record, and Judge (The Sequential Reading Loop)

For each chunk to be read:

1. **Unlock the Next Chunk (`next`)**:
   ```bash
   .agents/skills/lets-read/.bin/lets-read next --session "<session_dir>"
   ```
   This unlocks the next chunk into `<session_dir>/current_chunk.md`, writes the canonical reader prompt to `<session_dir>/current_prompt.md`, archives a permanent copy into `<session_dir>/chunks/chunk_XXXX.md`, updates `<session_dir>/story_so_far.md` (containing only chunks `1..current`), and prints spoiler-free metadata (`chunk_index`, `total_chunks`, `chapter_number`, `chapter_title`, `part_in_chapter`, `parts_in_chapter`, `word_count`, `subagent_prompt_file`).
   - *Guardrail*: `LetsRead.hs next` will refuse to advance if the previous chunk has not completed **both** `record` and `judge`.

2. **Invoke or Message `blind-reader` (Using `<session_dir>/current_prompt.md`)**:
   - **First chunk (or at a chapter boundary after >= 6 chunks when `LetsRead.hs next` returns `"rotate_subagent_recommended": true`)**: Call `invoke_subagent` with `TypeName: "blind-reader"` and `Role: "Blind Story Reader"`.
   - **Consecutive chunks**: Call `send_message` to the active `blind-reader` `conversationId` so it retains immediate conversational momentum across multi-part chapters.
   - **Prompt to `blind-reader`**: Read `<session_dir>/current_prompt.md` and pass its exact text to `blind-reader` (never paste `current_chunk.md` or `memory.md` inline).

3. **Record `blind-reader`'s Commentary, New Prediction, Conditional Retirement & Memory (`record`)**:
   Pass `blind-reader`'s `logAbsoluteUri` directly via `--subagent-log` (or write its full reply to `<session_dir>/last_response.md` and pass `--response-file`):
   ```bash
   # Option A (Direct extraction from subagent log — zero file-writing or Python needed):
   .agents/skills/lets-read/.bin/lets-read record \
     --session "<session_dir>" \
     --subagent-log "<blind_reader_logAbsoluteUri>"

   # Option B (From last_response.md written via write_file):
   .agents/skills/lets-read/.bin/lets-read record \
     --session "<session_dir>" \
     --response-file "<session_dir>/last_response.md"
   ```
   `LetsRead.hs record` automatically:
   - Splits `=== COMMENTARY ===`, `=== CHUNK SUMMARY ===`, `=== PREDICTION UPDATES ===`, and `=== UPDATED MEMORY ===`.
   - Adds `blind-reader`'s new prediction as `ACTIVE`, stores any conditional `RETIRED` nomination in `.state.bin` (without retiring it yet), and generates `<session_dir>/current_judge_prompt.md` containing the inline canonical lines of all active predictions (including the newly created prediction and any conditional retirement nomination).
   - Outputs `"status": "awaiting_judge"` and `"judge_prompt_file": "<session_dir>/current_judge_prompt.md"`.

4. **Invoke or Message `prediction-judge` (Using `<session_dir>/current_judge_prompt.md`)**:
   - **First chunk (or whenever `blind-reader` was rotated via `"rotate_subagent_recommended": true`)**: Call `invoke_subagent` with `TypeName: "prediction-judge"` and `Role: "Impartial Prediction Judge"`.
   - **Consecutive chunks**: Call `send_message` to the active `prediction-judge` `conversationId`.
   - **Prompt to `prediction-judge`**: Read `<session_dir>/current_judge_prompt.md` and pass its exact text to `prediction-judge`.

5. **Apply Judge Verdicts & Conditional Retirement (`judge`)**:
   Pass `prediction-judge`'s `logAbsoluteUri` via `--subagent-log` (or write its reply to `<session_dir>/last_judge_response.md` and pass `--response-file`):
   ```bash
   # Option A (Direct extraction from prediction-judge subagent log):
   .agents/skills/lets-read/.bin/lets-read judge \
     --session "<session_dir>" \
     --subagent-log "<prediction_judge_logAbsoluteUri>"

   # Option B (From last_judge_response.md written via write_file):
   .agents/skills/lets-read/.bin/lets-read judge \
     --session "<session_dir>" \
     --response-file "<session_dir>/last_judge_response.md"
   ```
   `LetsRead.hs judge` automatically:
   - Applies `prediction-judge`'s `CONFIRMED`, `DEBUNKED`, `SUBVERTED`, and `ACTIVE` verdicts to all active predictions (including any prediction `blind-reader` nominated for retirement).
   - **Conditionally applies `blind-reader`'s retirement nomination ONLY if more than 10 active predictions remain after `prediction-judge`'s verdicts** (skipping any candidate the Judge already resolved).
   - Appends `> [!NOTE]\n> **Prediction Judge Rulings (Chunk XXXX)**:` to `<session_dir>/entries/chunk_XXXX.md` and rebuilds `<session_dir>/lets_read_log.md`.
   - Updates `### Latest Prediction Judge Rulings` in `<session_dir>/memory.md` (and `<session_dir>/archive/memory/chunk_XXXX.md`), `<session_dir>/predictions/pred_XXXX.md`, `<session_dir>/predictions/by_chronology.md`, and `<session_dir>/predictions/by_topic.md` so `blind-reader` sees the Judge's rulings at the start of Chunk $N+1$.
   - When the final chunk of the story is judged (`is_finished: true`), generates `<session_dir>/predictions/hall_of_fame.md` and appends the complete **Prediction Hall of Fame & Shame** retrospective to `<session_dir>/lets_read_log.md`.
   - Outputs `"status": "judged"`.

### Step 5: Interactive Discussion vs. Batch Progression

- **In Interactive Mode**:
  - Present the recorded entry (`<session_dir>/entries/chunk_XXXX.md`, which includes both `blind-reader`'s commentary and the `> [!NOTE] **Prediction Judge Rulings (Chunk XXXX)**:` callout) to the user, always prefixed with a third-person host attribution banner (`> **Let's Read Host** — Relaying from \`blind-reader\` & \`prediction-judge\` (Chunk XXXX/YYYY):`), and link to `<session_dir>/lets_read_log.md`, `<session_dir>/memory.md`, `<session_dir>/predictions/by_chronology.md`, and `<session_dir>/predictions/by_topic.md` (plus `<session_dir>/predictions/hall_of_fame.md` when finished).
  - If the user replies with comments, questions, or non-spoiler discussion before asking for the next chunk:
    1. **Never answer in your own voice**: Forward their message (scrubbed of any spoilers, if applicable) to the `blind-reader` subagent via `send_message` so the reader persona can discuss theories with the user like a live forum thread host. Instruct `blind-reader` that if the exchange establishes or updates a factual/timeline correction, a craft/style course-correction, a running gag, a character status, or a mystery/prediction update, it **MUST** append `=== PREDICTION UPDATES ===` (if predictions changed) and/or a complete `=== UPDATED MEMORY ===` block (the 4 narrative sections) to its reply so `LetsRead.hs discuss` persists them across future subagent rotations.
    2. Run `LetsRead.hs discuss` (passing `--subagent-log "<subagent_logAbsoluteUri>"` or `--response-file "<session_dir>/last_response.md"`, and passing `--user-message "<short comment>"` or `--user-file "<session_dir>/last_user_message.md"`):
       ```bash
       .agents/skills/lets-read/.bin/lets-read discuss \
         --session "<session_dir>" \
         --user-file "<session_dir>/last_user_message.md" \
         --subagent-log "<subagent_logAbsoluteUri>"
       ```
    3. Present `blind-reader`'s reply to the user prefixed with the third-person host banner (`> **Let's Read Host** — Relaying discussion reply from \`blind-reader\`:`).
- **In Batch Mode**:
  - Repeat Step 4 (`next` $\rightarrow$ `blind-reader` $\rightarrow$ `record` $\rightarrow$ `prediction-judge` $\rightarrow$ `judge`) until the target number of chunks/chapters (or `"status": "finished"`) is reached.
  - Whenever `LetsRead.hs next` outputs `"rotate_subagent_recommended": true` (at a chapter boundary after >= 6 chunks), start fresh `blind-reader` and `prediction-judge` subagent instances via `invoke_subagent` so their context windows stay sharp.
